THE PROBLEM (founder review of the newton_third_law rebuild, 2026-07-29):
The push-off apparatus works correctly - at t=0 the compressed spring, both equal-and-opposite arrows, and the HUD (F = 30.00 / -30.00 N, a = 7.50 / -2.50 m/s2) are all exactly right. But the interaction lasts only release_at_ms = 420 ms out of an ~11 SECOND state. By t = 1000 ms the carts have separated, the forces are zero, so the arrows hide and the spring hides, and the HUD reads 0.00. For 96% of the state there is nothing on screen but two blocks sitting apart, and the canonical frozen reviewer frame landed in that dead zone showing NONE of the lesson.

This is not fixable by authoring. A spring push-off with classroom-visible force magnitudes is inherently fast (t = sqrt(2*stroke/a_rel); getting a 2 s contact out of the 0.88 m stroke would need ~1.3 N, far below the arrow-length floor). And the state cannot simply be made 2 s long because Rule 31 requires 25-55 words of narration, which is 10-20 s.

THE FIX: let the interaction REPEAT within the state, the way a teacher repeats a demo. Add to the push_off block:

    repeat_every_ms?: number;   // re-arm the whole interaction on this cycle; omit = fire once

Semantics:
  cycle  = floor(t_ms / repeat_every_ms)
  phase  = t_ms - cycle * repeat_every_ms
  - contact when contact_from_ms <= phase < release_at_ms (phase, NOT raw t_ms)
  - when `cycle` changes from the previous frame, RE-ARM: restore every body's s and v from its s0/v0 seeds and re-compress the spring. nlbResetTrajectory() already does exactly this rewind - reuse it, do NOT write a second rewind path. Do NOT reset eng.t_ms (that would re-trigger immediately); keep the master clock monotonic and derive cycle/phase from it.
  - omitted => behave exactly as today (single fire). No existing authored state may change behaviour.
